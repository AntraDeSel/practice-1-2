## Шаг 5. Как проверять свою работу

Для каждого задания из заданий 2-6 есть **три команды**. Все три должны пройти без ошибок.

### 1. Проверка на `any`

```bash
npm run lint
```

Ищет `any` в вашем коде. Если найдёт — покажет файл и строку:

```
src/task2-any.ts:1:32 - error: Unexpected any. Specify a different type.
```

**Что делать:** заменить `any` на конкретный тип (`number`, `string`, `boolean`, `<T>` и т.д.).

### 2. Проверка типов

```bash
npm run check
```

Запускает компилятор TypeScript. Ловит ошибки типов: несовместимые типы, забытые `null` и `undefined`, отсутствующие свойства.

Пример:

```
src/task3-null.ts:4:10 - error TS18047: 'user.email' is possibly 'null'.
```

**Что делать:** прочитать сообщение, оно подскажет, что не так. Обычно нужно добавить проверку на `null` / `undefined`.

### 3. Проверка логики

```bash
npm test -- task2
```

Запускает рантайм-тесты. Проверяют, что функции работают правильно.

```
✓ tests/task2.test.ts (3 tests)
Test Files  1 passed (1)
     Tests  3 passed (3)
```

**Что делать:** если тест упал — посмотреть, что именно не так, и исправить логику функции.


## Шаг 6. Работа над заданием 2 (пример)

Задание 2 находится в `src/task2-any.ts`. Там три функции с `any`. Ваша цель — заменить `any` на конкретные типы.

**До:**

```typescript
export function calculateDiscount(price: any, discount: any): any {
  return price - discount;
}
```

**После:**

```typescript
export function calculateDiscount(price: number, discount: number): number {
  return price - discount;
}
```

**Алгоритм:**

1. Откройте `src/task2-any.ts`
2. Запустите `npm run lint` — увидите, где `any`
3. Подумайте, какой тип **должен** быть на самом деле
4. Замените `any` на этот тип
5. Запустите `npm run lint` снова — если чисто, переходите дальше
6. Запустите `npm run check` — убедитесь, что нет ошибок типов
7. Запустите `npm run test` — убедитесь, что логика не сломалась

### Подсказка для `getFirstElement`

Эта функция должна работать с массивом **любого** типа. Для этого нужны дженерики:

```typescript
export function getFirstElement<T>(arr: T[]): T | undefined {
  return arr[0];
}
```

- `<T>` — параметр типа
- `arr: T[]` — массив элементов типа `T`
- `T | undefined` — потому что массив может быть пустым

## Частые вопросы

### Я запустил `npm run test`, все тесты прошли, но я не менял `any`. Это нормально?

Да, это нормально. Рантайм-тесты проверяют **логику**, а не типы. Чтобы проверить типы, запустите `npm run lint` и `npm run check`.

### `npm run check` показывает ошибку, но я не понимаю, что она значит

Прочитайте текст ошибки. TypeScript обычно объясняет, в чём проблема:

- `possibly 'null'` — значение может быть `null`, добавьте проверку
- `possibly 'undefined'` — значение может быть `undefined`, добавьте проверку
- `is not assignable to` — тип не подходит, посмотрите на ожидаемый тип

Если не получается — напишите в чат курса, поможем.

### Я не могу запушить в оригинальный репозиторий

И не нужно. Вы пушите **в свой форк**. PR создаётся из вашего форка в оригинал.

### Как мне обновить свой форк, если преподаватель что-то поменял?

В терминале:

```bash
git remote add upstream https://github.com/ПРЕПОДАВАТЕЛЬ/practice-1-1.git
git fetch upstream
git merge upstream/main
```

Но обычно это не требуется на одной практике.

### Что делать, если я случайно поменял файл в `tests/`?

Откатить изменения:

```bash
git checkout tests/
```

### Где смотреть, что я должен сделать в задании 3, 4, 5?

В файлах `src/task3-null.ts`, `src/task4-union.ts` и т.д. — там комментарии с описанием задания.

## Полезные команды (шпаргалка)

| Команда | Что делает |
| :--- | :--- |
| `npm install` | Установить зависимости |
| `npm run lint` | Проверить код на `any` |
| `npm run check` | Проверить типы через `tsc --noEmit` |
| `npm run test` | Запустить рантайм-тесты |
| `npm run lint && npm run check && npm run test` | Полная проверка |
| `git status` | Посмотреть, какие файлы изменены |
| `git diff` | Посмотреть, что именно изменено |
| `git add src/` | Добавить изменения в `src/` к коммиту |
| `git commit -m "сообщение"` | Сделать коммит |
| `git push origin main` | Отправить коммит в свой форк |
